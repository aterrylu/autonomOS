Two status notes that matter for planning:
- **Gemini CLI consumer retirement.** Google announced (2026-05-19) that Gemini CLI stops serving free/Pro/Ultra users on 2026-06-18 in favor of **Antigravity CLI**; Code Assist Standard/Enterprise unaffected; the OSS repo keeps releasing. Antigravity reuses `~/.gemini/`. Any Gemini-specific memory integration is a moving target.
- **Anthropic API memory tool** (`memory_20250818`): a client-side file protocol (`view/create/str_replace/insert/delete/rename` under `/memories`) with an auto-injected "ALWAYS VIEW YOUR MEMORY DIRECTORY… ASSUME INTERRUPTION" prompt. API-only and Claude-only; Claude Code's auto-memory is a separate product feature.

All three stores are **machine-local, single-user, and keyed by something other than agent identity** (repo / user / project). None is reachable by the other two CLIs.

## 5. Cross-provider MCP mechanics (how one memory server reaches all three CLIs)

- **Claude Code:** `--mcp-config` (autonomOS already passes it, `providers/claude-code.ts`); auto-allow via `permissions.allow: ["mcp__autonomos__recall", …]` in the same inline `--settings` payload.
- **Codex:** `-c mcp_servers.<name>.command=…` overrides (autonomOS already injects `mcp_servers.autonomos.*` this way, `providers/codex.ts`); approval per server via `default_tools_approval_mode` or per tool via `tools.<t>.approval_mode`; tools with `readOnlyHint` skip prompts under the default mode (ADR-085 measurement).
- **Gemini:** `mcpServers.<name>` in the settings file autonomOS writes (`$configDir/gemini-settings.json`); `trust: true` or `includeTools` to skip prompts; server name must not contain `_`; host env vars matching `*TOKEN*|*SECRET*|*KEY*` are **redacted from stdio servers unless listed in `env`** (the token-file delivery in #297 exists for exactly this reason).
- Streamable HTTP with static headers works on all three (`http_headers` / `headers`), so a server living inside the autonomOS process is as reachable as a stdio subprocess — but the existing channel-server subprocess is the path of least resistance: it is already spawned per agent, already token-authenticated, and already the thing that knows which agent is calling.
