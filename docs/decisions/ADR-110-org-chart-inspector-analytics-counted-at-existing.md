## ADR-110: Org Chart inspector analytics — counted at existing chokepoints, in memory, honest per runtime

- **Date:** 2026-09-24 · **Decided by:** Terry (approved the rich inspector design: "as much information as possible in the detail panel", with the honesty rule that per-provider gaps show as n/a and the account-wide usage windows are never split per agent), built by OrgChart@autonomOS.
- **Context:** The server kept only each agent's CURRENT activity state, so the inspector couldn't say how long an agent had been waiting, how many turns it ran, which tools it used, or whether it had been restarting.
- **Decision:**
  1. **Count at chokepoints that already exist; estimate nothing.** `agents/analytics.ts` taps: `emitStatusDelta` (every activity-state change from the hook relay, Codex's daemon feed, and compaction) for time in state, turns (working → idle/ready), waits on a human (needs_input spans, including an open one) and a 24h transition ring; hook ingest (PreToolUse / PostToolUseFailure) for tool counts by name, failures and the last tool; the spawn site in `spawnAgent` right after the record resolves, on both the fresh-insert and reattach paths (starts → restarts; NOT `markRunning`, which a fresh spawn never calls and the crash net also calls for an identity-only reset), `markExited` (crashes only, since a user kill isn't a crash; it also CLOSES the state as `stopped`, because a kill or crash sends no SessionEnd, and otherwise an open wait would keep growing and a resume's first ready would count as a phantom turn), and the PTY exit (last exit code, recorded past the stale-PTY guard). The git branch is read with an async, cached `git branch --show-current` under a scrubbed git env (an inherited `GIT_DIR` would answer for the outer repo), never blocking the event loop.
  2. **In memory, labelled as such.** Every number is "since the server started" (the response carries `since`; the panel says so). Persisting counters is deferred: it adds schema and retention for a first version whose value is the live view.
  3. **Honest per runtime.** `support` flags per provider: Codex has no per-tool events and no needs-input signal, and Gemini has no tool failures. The panel renders "n/a for Codex" (and so on), never a zero that looks like a measurement.
  4. **Bounded.** Transitions are capped (600, pruned to 24h) and distinct tool names are capped (64; every call still counts). Stats are dropped on hard delete.
  5. **Usage (context %, cost, model) is NOT collected here.** It comes through TerminalRender's single shared statusline mechanism (agreed interface: per-agent snapshot on `/ws/agents`, null = not reported), so there is one path for those fields.
- **Rationale:** each tap is a line at a place that already sees the event, so accuracy follows from the existing state machine instead of a parallel one. Labelling the window and the per-runtime gaps keeps the panel trustworthy.
- **Alternatives considered:** **Deriving from transcripts (JSONL/rollouts)** was rejected: it's provider-specific parsing, heavier, and duplicates what the hook relay already reports. **Persisting counters now** was deferred (see 2). **Showing 0 for unsupported fields** was rejected: a zero reads as "measured, none".
