## ADR-117: Sign-in link: token in the URL fragment, exchanged for the cookie (supersedes ADR-052's no-link position)

- **Date:** 2026-09-26
- **Decided by:** UsageBars@autonomOS (agent), on a decision Terry explicitly delegated ("consult more subagents from a security perspective, then use their best judgement… they can make the decision for me and commit and merge the PR"), relayed by TeamLead@autonomOS. Three independent security-review subagents plus SecurityAudit-Claude@autonomOS were consulted; where they split, the split and the call are recorded below.
- **Context:** Terry asked for a magic-link login: open a link that carries the token and be logged in, with a clean URL afterwards. ADR-052's 2026-06-29 security update had removed the installer's `…/auth?token=` link because it leaked (shell scrollback, `ps` args of the browser opener, browser history) and never worked (no route consumed it). Its closing note left two things open: `requireAuth` still ACCEPTED `?token=` on every public `/api/*` and `/ws/*` route, and zero-paste login was deferred. Two facts found while designing this also shaped it. Session cookies are host-scoped, not port-scoped, so every autonomOS instance on one host (Terry's live `:3100`, a QA instance, a worktree dev server) shared the one `autonomos_token` cookie and overwrote each other's login. And the only production sender of `?token=` is the channel server dialing `/ws/gateway` on the INTERNAL Unix socket; nothing on the public listener needs it.
- **Decision:**
  1. **The link is `http(s)://<host>/#token=<token>`.** The token rides in the URL fragment, which browsers never send to the server, a proxy, a tunnel or a `Referer` header. The installer's connect panel and `--print-url` print this form.
  2. **An inline script, the FIRST script in `index.html`, consumes it.** It reads the token, strips it from the address bar with `history.replaceState` BEFORE anything else (so a failed bundle load cannot leave it there), then POSTs it same-origin to `POST /api/auth`, which sets the httpOnly cookie. The React bundle only ever sees the exchange's result (`window.__autonomosLinkLogin`), never the token. While it settles the page shows "Signing you in…".
  3. **A refused link never clears a working session.** After the exchange the app PROBES; the probe, not the exchange, decides the state. Signed out with a refused link, the login page shows "That sign-in link didn't work. It may be from another autonomOS instance, or the token has changed. Paste the current token instead." (`role="alert"`). An exchange that got no answer (network, 15-second timeout, 5xx) says the server couldn't be reached instead, and one the server accepted whose cookie didn't stick says so. Every failure is logged to the console with its status. A refused exchange sends no `Set-Cookie`.
  4. **The session cookie is named per port** (`autonomos_token_<port>`), so instances on one host stop overwriting each other. The legacy `autonomos_token` is still READ, and a request that authenticates on it is answered with the per-port cookie, so an upgrade logs nobody out and the browser leaves the shared cookie behind after one request (after that, an older-build instance on the same host rewriting the shared cookie can't log it out). Every credential a request carries is tried, and the first VALID one wins, not the first present: a stale legacy cookie from another instance must not shadow a good per-port cookie or Bearer header.
  5. **Public-listener `?token=` is deprecated for one release.** It still authenticates, and the first use per process logs a warning naming the route prefix, never the value. It is consulted only when no cookie or Bearer header is present. The internal socket's `/mcp` and `/ws/gateway` keep accepting it silently. The three in-repo public callers (the perf spec, two usage-queue integration suites) moved to `Authorization: Bearer` (verified on Node 22's undici WebSocket, CI's version) or to the link.
  6. **Legacy `?token=` LINKS are stripped and honored for one release.** A bookmarked or previously-printed `/?token=` still works, and the inline script strips it the same way. Nothing prints that form any more. When both are present the fragment wins, and both are stripped.
  7. **The shell (`index.html`, on 200, 304 and the SPA fallback) is served `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`.** Hashed assets are unchanged.
  8. **`--print-url` writes to the terminal only.** It bypasses the logger's tee (`writeUnlogged`), so the link never lands in `$configDir/logs/autonomos.log`. The installer's `--open` still opens the bare dashboard root: a token-bearing URL passed to `open`/`xdg-open` would show in `ps` to every UID on a shared host.
- **Rationale:** The fragment carries the token only as far as the browser, and that is the property every other placement lacks. `?token=` reaches server access logs, reverse-proxy and tunnel logs, and `Referer` headers; that is exactly what ADR-052 removed, so reviving it was a non-starter. Stripping before the exchange and exposing only the result keeps the token out of the app's reach and out of the address bar even when the bundle fails. The probe-decides rule means clicking an old link while signed in can never be a logout, the failure mode Terry is most likely to hit with two instances on one box. The per-port cookie removes the cross-instance overwrite that would otherwise make "open the QA instance's link" silently sign `:3100` out. Deprecating public `?token=`, rather than keeping or removing it outright, closes ADR-052's deferred accept-side vector with one warned release for any unknown curl/script consumer (the ADR-084 alias pattern). The shell headers make sure a token-bearing URL is never cached, never leaks as a `Referer` to anything the page links to, and never renders inside another site's frame (clickjacking the auto-login).
- **Alternatives considered:**
  - **`?token=` query link.** Rejected unanimously: it is the ADR-052 leak.
  - **One-time `#code=` nonce links (5-minute expiry, server-side exchange).** The strongest option (a leaked link goes stale). Deferred, not rejected. A short expiry conflicts with Terry's workflow of opening a printed link later, and it needs a code store plus a CLI verb to mint codes, which is net-new auth surface. It is the first follow-up below.
  - **Refuse legacy `?token=` links outright (SecurityAudit's preference).** Reviewers split 2–1 for one warned release. Chosen: honor and strip for one release, print only `#token=`. Refusing breaks existing bookmarks with no benefit the strip doesn't already give: the query has already crossed the wire by the time the page loads, so refusing it protects nothing.
  - **Let the bundle read the token (no inline script).** Rejected. The token would sit in the address bar until the bundle loaded, and stay there if it failed to load; any bundle code (or a compromised dependency) could read it.
  - **Keep one shared cookie name.** Rejected: instance collisions on one host.
  - **A rate limiter on `/api/auth` in this PR.** Out of scope (SecurityAudit: "Don't build a limiter yourself"); tracked as the V2 limiter.
- **Residual risks (accepted, named):**
  - The pre-strip history entry: the address bar is rewritten, but a browser with history sync can capture the URL before `replaceState` runs, and the Navigation Timing entry keeps the original URL for the page's lifetime.
  - Browser extensions with tab/URL access see the link before it is stripped.
  - Stripping requires JavaScript. A no-JS load leaves the fragment in the address bar (it is still never sent anywhere).
  - The link is printed in the operator's terminal, so it lives in scrollback. When a recipe runs inside an agent's PTY, it also lands in the PTY replay buffer and that agent's transcript. Under the service, stdout's sink is `/dev/null`; a custom supervisor that captures stdout would capture it.
  - No expiry and no logout: the link, and the cookie, equal the admin token until the token is rotated.
  - The cookie VALUE is the admin token. The legacy-named cookie (still read, no longer written) is sent to every localhost port.
  - The default bind is all interfaces, so over plain `http://` on a LAN the exchange and the cookie cross the network in cleartext (unchanged by this ADR; use loopback, Tailscale or a TLS proxy).
  - Compat `?token=` (public API and legacy links) keeps exposing the query to proxy/tunnel logs for one more release.
- **Follow-ups:** (1) nonce `#code=` links minted by a CLI verb; (2) a random session-id cookie instead of the token itself (enables logout and expiry); (3) a `Host` allowlist against DNS rebinding; (4) require `Sec-Fetch-Site: same-origin|none` (never `same-site`) on `POST /api/auth`; (5) the V2 `/api/auth` rate limiter; (6) remove public-listener `?token=` and the legacy-link path next release; (7) move `/ws/gateway` auth to a header (needs a `channel-server/dist.mjs` rebuild); (8) token rotation (SecurityAudit recommends rotating the live token, and a `rotate` verb makes that one step).
- **Source:** TeamLead@autonomOS channel (Terry's request and delegation), SecurityAudit-Claude@autonomOS checklist, three security-review subagents, and the magic-link PR (`terry/magic-link-login`).
