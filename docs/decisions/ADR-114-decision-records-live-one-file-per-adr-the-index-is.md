## ADR-114: Decision records live one file per ADR; the index is regenerated after merge

- **Date:** 2026-09-25
- **Decided by:** Terry (approved the per-file migration, including the CI check and the index); TeamLead@autonomOS (PRs never touch the index: a post-merge workflow regenerates it); implemented by Decisions@autonomOS.
- **Context:** Five or six agents open PRs in parallel, and each appended its ADR to the single `docs/DECISIONS.md`. Every merge re-conflicted every other open ADR-bearing PR, and because main requires branches to be up to date, each conflict forced a rebase and a fresh review. Numbers collided constantly: on 2026-09-25 two open PRs both claimed ADR-103, and another claimed ADR-104, which main already had.
- **Decision:**
  1. One file per decision, `docs/decisions/ADR-NNN-<kebab-slug>.md`. The 108 existing entries were migrated verbatim. `docs/decisions/legacy-manifest.json` records each file's sha256, the separator bytes removed, the original order and the original log's sha256. `scripts/decisions.test.ts` proves the files reassemble into the old log byte for byte. Historical numbering quirks are kept: a repeated number gets a letter suffix in its filename only (the second ADR-029 is `ADR-029b-…`).
  2. `docs/DECISIONS.md` stays as a pointer stub, pinned byte for byte.
  3. `scripts/decisions.ts check` runs first in `make check`. It hash-locks migrated entries. For new entries it enforces filename/header agreement and the required fields (Date, Decided by, Context, Decision, Rationale, Alternatives considered, Source), all non-empty and free of template TODOs. It rejects duplicate numbers, except grandfathered history, and its error tells whoever merges later to run `make adr-renumber`.
  4. `make adr NEW="…"` allocates the next free number from the local tree, origin/main and open PRs (via gh; if gh is unavailable it warns and falls back).
  5. The index `docs/decisions/README.md` is generated. PRs don't edit it. The decisions-index workflow regenerates it after each push to main and delivers it as one rolling "docs(decisions): regenerate index" PR, opened with RELEASE_PAT (author aterrylu, reviewed and approved by nox), with auto-merge on.
- **Rationale:** Parallel PRs now touch disjoint paths, so an ADR no longer causes a conflict. A number collision is a one-file rename, caught before merge because CI always re-runs against current main (strict up-to-date). Any index committed by PRs would have been the next shared hotspot, since every ADR PR adds a row at the same spot. The rolling bot PR keeps the index current without weakening the no-bypass ruleset. Hash-locking migrated entries turns "never modify past entries" from a convention into a CI failure.
- **Alternatives considered:** Keep the single file and resolve conflicts by hand (the status quo: a rebase and re-review per merge). A committed index that each PR regenerates, with a git merge driver (still conflicts through GitHub's "Update branch"; rejected by TeamLead). No committed index at all (loses the browsable table). A bot that pushes the index straight to main (needs a ruleset bypass actor; the ruleset is deliberately no-bypass). Renumbering historical duplicates to clean them up (rewrites history that code comments cite; rejected in favor of filename-only suffixes). Timestamp or UUID ids instead of numbers (breaks every existing "ADR-NNN" reference).
- **Supersedes:** nothing. This changes where decisions are recorded, not any past decision.
- **Source:** Terry's approval relayed by TeamLead@autonomOS in the autonomOS agent channel (2026-09-25); design review with TeamLead; the PR that introduced `docs/decisions/`.
