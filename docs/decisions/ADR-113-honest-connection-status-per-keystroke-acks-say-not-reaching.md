## ADR-113: Honest connection status — per-keystroke acks say "Not reaching server" in ~1s; a heartbeat covers idle time; no keystroke is ever delivered late

- **Date:** 2026-09-24 → 2026-09-25 · **Decided by:** Terry (reported the lagging "Connected"; picked the timings; kept typing live; per-cause wording; then, after trying the gate: "12s is a little bit too long … maybe the gate should be when I type but the server isn't receiving it? Even 5s might feel too long") via TeamLead; investigation + implementation by TerminalRender@autonomOS.
- **Context:** Terry typed into an agent, nothing happened, and the status bar kept saying "Connected" until it flipped "after a while". Measured on an isolated rig (real Claude Code agent, a pausable TCP proxy for a true half-open link): the dot was an HTTP poll of `/api/host` (20s cadence, 4s timeout, two failures) tied to neither WebSocket — 15.6s (range 10–30s) to notice a SIGSTOPped server, 33.7s for a half-open link; the terminal socket had no heartbeat and never closed in 150s; a SIGSTOPped agent sat behind a green "Connected" and a "Ready" sidebar indefinitely. Also measured: `close()` on a half-open socket leaves it in CLOSING and `onclose` never fires, so onclose-gated reconnects never happen; keystrokes sent on an abandoned half-open socket were **delivered to the agent when the link recovered** (a silent late burst); and every socket open's scrollback replay made xterm re-answer old terminal queries as if typed (`1;2c1;2c1;2c` landed in gemini's prompt — pre-existing on every reconnect and page reload).
- **Decision:**
  1. **Per-keystroke acknowledgement (revision 2 — the primary signal while typing).** A negotiated binary control plane: terminal bytes stay in TEXT frames both ways; after the server advertises support (`;input-ack=1` on the end-of-replay OSC 7777 marker, requested with `?inputAck=1`), the pane sends keystrokes as binary `[0x01][seq][sentAtMs][bytes]` frames and the server replies `[0x02][seq]` **after** `pty.write` succeeds. An older server never receives a binary frame (so nothing is typed as garbage); an older dashboard never asks. On a negotiated socket the server treats binary as ack frames ONLY: a malformed or unknown-type binary frame is dropped and logged, never written (found live — a harness speaking an older frame layout typed its header bytes into an agent's prompt). Measured on real agents at load avg 23–47 (idle and mid-turn Claude Code, Gemini): **ack p99 ≤ 31ms, first-echo p99 ≤ 67ms**. Thresholds sit 15–30× above: an unacked key at **1s → "Not reaching server… · N keystrokes waiting"**; at **3s → give up** (the keys are counted *not sent* — exactly, because the server refuses frames older than 2.5s — and the pane reconnects); an acked printing key with no echo at **2s → a subtle "Waiting for agent…"** (muted, no border, same position — no layout shift, no color alarm), at **5s → "Agent not responding · Ns"**. Live: first unacked key → chip at 1.28s, give-up at 3.1s, the four abandoned keys never reached the agent. When only the browser→server direction dies, the server's own liveness ping (last pong ≤1s before the stall + 4s deadline) closes the socket ~3s in, so a key typed later than ~2s into that stall goes straight to "Connection lost"; its notice then says "may not have been sent", because a socket closed under a key younger than the give-up cannot prove the key never landed (measured: pause at t, keys at t+2.37s, lost at t+3.03s).
  2. **The status bar follows the `/ws/agents` heartbeat** (idle-time detector): server ping every **2s**; stale after **5s** → "Reconnecting… last heard Ns ago" → "Disconnected · retrying" at 20s. A stale socket is abandoned and replaced at once (never gated on `onclose`); hung handshakes abandoned after 5s; `offline`/`online`/tab-visible re-check at once. The `/api/host` poll remains only until the socket has opened once. Transport stale ⇒ every pane is cut loose and reconnected on recovery.
  3. **No late keystroke burst — three server mechanisms.** (a) A superseded-socket fence (`?client=<page>&gen=<page-wide counter>`) drops input on an older socket once a newer one from the same client opened — the counter is page-wide because a per-pane counter restarting at 1 would sit below a stale binding and have its healthy socket fenced (caught in review). (b) The server pings every terminal socket at the WebSocket protocol level (1s) and terminates one silent for 4s — the fence alone lost the race when the old socket's retransmit beat the replacement (caught in review; live: link resumed at 10.7s, the server had terminated the socket at 7.3s, nothing late arrived). After its OWN event-loop stall the server grants a fresh deadline instead of killing a healthy socket. (c) Acked frames carry the client's send time relative to the connection's own open; the server drops (never writes, never acks) a frame older than 2.5s — below the pane's 3s give-up — which also closes the one residual revision 1 had to accept (a stalled *server process* writing keys late on resume).
  4. **Typing stays live** (Terry overrode pausing). Keys the socket can't carry are dropped and **counted**, Esc/Ctrl+C and mod-key bindings included; mouse and focus reports and terminal replies are sent but never counted. The pane shows the count while reconnecting and for 8s once seen: "weren't sent" when every drop is known unwritten, "may not have been sent" otherwise.
  5. **Fallback for servers without acks:** revision 1's per-pane watchdog (5s of total silence → `GET /api/agents/:id/io` for input/output ages → "Connection lost" or "Agent not responding"; 404 stands down; failures back off and reconnect after 3).
  6. **Agent chips only where measured, and never at a dialog:** Claude Code 2.1.281, Codex 0.154.0 and gemini-cli 0.46.0 were each measured to keep echoing mid-turn; a new provider stays off until measured. Suppressed while the agent's status is `needs_input` (a permission or choice dialog is on screen).
  7. **Replay reply filter:** with `?replayMark=1` the server sends the OSC 7777 marker right after the replay; the pane drops xterm's query replies until it is PARSED (not a timer — a fixed window both leaked on slow replays and swallowed a fresh agent's live startup queries; caught in review).
- **Rationale:** An acknowledgement is the only signal that reflects "my typing isn't arriving" in about a round trip; heartbeats measure idle links and TCP can take minutes. The measured latencies make the 1s/2s/3s/5s thresholds safe on a heavily loaded box, and each threshold only fires when the thing it names is actually true. Negotiation keeps every mixed-version pairing safe, because the terminal socket treats unknown text as keystrokes.
- **Alternatives considered:** **pause input while reconnecting** (recommended in Phase 1; declined by Terry); **a faster heartbeat alone** (Terry: even 5s feels long while typing — only an ack answers at typing speed); **acks as JSON messages on the text channel** (rejected — an older server would type them into the agent); **client-side buffering and replay of unacked keys** (rejected — a late delivery of abandoned input is exactly the double-submit hazard); **faster `/api/host` polling** (can't see a stuck agent).
- **Review:** two independent pre-PR reviews (correctness, silent failures) found the per-pane generation reset, the fence ordering race, the timer-based replay window, the probe retry loop, uncounted interrupt keys and a health-listener gap; all fixed. Every rule of both revisions is mutation-verified.
