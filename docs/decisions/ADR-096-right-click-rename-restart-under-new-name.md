## ADR-096: Right-click Rename = restart-under-new-name

- **Date:** 2026-09-09 · **Decided by:** Terry (design specced in ADR-093's deferred section; refinement + "build it" relayed via TeamLead)
- **Context:** The agent-row context menu (ADR-093) shipped without Rename — deferred over a CC `customTitle` ownership wrinkle and a PTY-injection concern. Terry brought it back with a concrete motivation: people trying autonomOS resume agents from the Projects tab from existing Claude Code sessions that "never had a name to begin with," and there was no way to give them one. His refinement: warn that renaming restarts the session.
- **Decision:** Rename an agent by **restarting it under a new name**, not by mutating a live process. Flow: the context menu's **Rename…** item (running rows) swaps the menu body for a name input pre-filled with the current name + the warning *"Renaming restarts this session — the conversation resumes."*; on submit, `store.renameSession(id, name)` (1) `PATCH /api/agents/:id` → `patchAgent(id, {name}, version)` to make the **record name** authoritative, then (2) restarts (kill → attach) so the resume argv carries the new `--name`, then (3) `switchPane` returns the pane focused (the #353 re-open-after-attach fix, reused). The once-removed `PATCH /:id` route is re-added on the body-`version` optimistic-concurrency convention. A namesake collision (another RUNNING agent already holds the name) is a **409 at PATCH time** — before anything is torn down — mirroring `spawnAgent`'s guard so the restart's attach can't leave the agent stopped under a half-applied rename. Empty/whitespace names are rejected (zod `min(1)` + a route trim); an unchanged name is a client-side no-op (never a bare restart). The rename rethrows BEFORE the restart, so a failed rename kills nothing; the inline form shows the reason and stays open (mirrors the Delete inline-confirm).
- **Rationale:** A CC agent's name is baked in at spawn via `--name`; there is no live-rename primitive. Restart-under-new-name dissolves the two deferral blockers at once — **no PTY injection** (the name rides the resume argv, not a keystroke stream) and **no record-vs-CC-title divergence for the common case** (an adopted session that "never had a name" has no in-session `/rename` `customTitle`, so the new record name is authoritative everywhere). Reusing `restartSession` keeps the compose thin and inherits its pane-refocus fix. Patch-before-restart ordering is the correctness argument: attach re-reads `agent.name`, so the record must change first or the restart resurrects the old name.
- **The customTitle caveat (documented, per ADR-093's pre-authorization to "document that /rename-ed sessions keep their in-session title"):** `--name` on resume does not reliably rewrite the JSONL `custom-title`. For a managed agent the **sidebar/record** name is authoritative (unaffected), and the motivating no-name case has no `customTitle` so the new name sticks everywhere. But a session that was `/rename`-d **inside Claude** keeps that in-session title on the **Projects tab** (`projects.ts` prefers `s.customTitle`) and in **name-based lookups** (`resolveAgentId` compares `title ?? a.name`) until the user `/rename`s in-session again. Accepted for v1; making the record name authoritative for managed agents in those two spots is a scoped follow-up.
- **Alternatives considered:** **live in-place rename via PTY `/rename` injection** (rejected — fragile keystroke stream, the original deferral blocker); **rename an EXITED/not-yet-adopted Projects session directly** (out of v1 — a pure-external session has no record to patch; the motivating flow is Resume→then→Rename on the now-running managed agent; a one-step "Resume as…" is a possible follow-up); **making the record name authoritative over `customTitle` in `projects.ts` + `resolveAgentId`** (deferred — larger blast radius into name resolution, not needed for the motivating case); **a modal dialog** (rejected — the in-menu inline swap matches the Delete-confirm pattern and Terry's "indicate that renaming restarts" framing).
- **Source:** Terry via TeamLead relay 2026-09-09 ("I'm definitely going to make the right click rename feature work… they never had a name to begin with"; "pop up a window or simply indicate that renaming the agent will automatically restart the session").
