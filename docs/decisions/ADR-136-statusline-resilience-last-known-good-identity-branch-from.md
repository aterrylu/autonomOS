## ADR-136: Statusline resilience: last-known-good identity, branch from HEAD

- **Date:** 2026-10-01
- **Decided by:** Performance@autonomOS (agent), on Terry's report relayed by TeamLead@autonomOS; TeamLead approved the direction after the measurements.
- **Context:** With 30-50 agents, the statusline's first line often flipped to `[autonomos · offline]` and the branch kept vanishing. Each tick is a fresh `node` process that spawned `git branch --show-current` (100ms budget) and fetched `/api/agents/:id/self` (200ms budget) with no memory between ticks. Measured on a 25-agent load rig (real server, stub agents running the real statusline): the `git` spawn missed its budget on 96-100% of ticks; a fresh process's first fetch costs 25-280ms of undici cold start before the request leaves; and any server block over ~150ms (a synchronous `ps -A` on every dashboard load, 965ms; the Projects poll re-reading untitled transcripts every 30s, ~160ms) timed out every in-flight tick at once. Live with real Claude Code 2.1.286: main's script showed no branch at rest, and `[autonomos · offline]` right after a 7s server freeze.
- **Decision:** The statusline keeps a per-agent last-known-good cache (`$AUTONOMOS_CONFIG_DIR/statusline-cache/<session>.json`: name, manager, project, reports, branch). Identity policy (`chooseIdentity`, pure and unit-tested): a fresh answer wins; a slow or failed answer shows the cached identity, as-is for 60s and dimmed after; "offline" only on a definitive answer (connection refused, 401, 404) or after 5 minutes with no fresh answer. The branch is read from `.git/HEAD` (following a linked worktree's `.git` file, walking up only to CC's project_dir), with the cached branch as the fallback on a read error; no `git` process. The fetch budget is 1.5s and starts before the branch read. The server removes an agent's cache on token revoke and sweeps day-old leftovers at boot, but keeps live caches across a restart so the boot stall doesn't flash "offline". Server side, the `ps` listing runs off the event loop (async, single-flight) and the title cache remembers "no title" by mtime.
- **Rationale:** Slowness is not evidence the server is gone: on a busy box the client's own cold start can eat the whole old budget. Showing the last good answer is correct for a value that changes rarely (an agent's name/manager/reports), and a refused connection still reads "offline" at once, so a real outage is not hidden. Reading HEAD is the same answer `git branch --show-current` gives (asserted in a test), without a process spawn per agent per tick, and it halves the statusline's spawns. Measured live: Claude Code accepts the slower answer (its duration counter advanced through the freeze and the identity held), so the longer budget doesn't blank the line.
- **Alternatives considered:** (1) Just raise the timeouts: a fresh process with no memory still has nothing to show on a miss, and a longer `git` timeout still costs a spawn per tick. (2) Cache in the server and have the statusline read a file: the real cure for the spawn storm (no `node` per tick at all); it belongs to TerminalRender's statusline redesign and is a larger change. This ADR is the robust interim. (3) Dim immediately on any miss: a busy box would flicker the whole fleet dim. (4) A `git` fallback when HEAD can't be read: reintroduces the spawn on exactly the ticks that are already slow; the cached branch is a better fallback.
- **Source:** Performance@autonomOS CC session, TeamLead@autonomOS channel (2026-10-01); PR "statusline never flips offline or drops the branch under load".
