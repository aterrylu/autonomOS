## ADR-099: Codex usage lanes — Codex-CLI-parity labels for KNOWN lanes, graceful raw render for UNKNOWN ones

- **Date:** 2026-09-12
- **Who:** Terry (picked option A of three mockups; set the future-safety requirement); investigation + implementation by the UsageBars agent.
- **Context:** Terry re-upped the $100 Codex plan and the popover showed lanes named `GPT-5.3-Codex-Spark` and `gpt-reserve`. He assumed these were stale mappings on our side and asked for a port from codexbar. Investigation (his live `/wham/usage` payload, one read-only GET; the codexbar main tree; the `openai/codex` TUI source) showed the opposite: autonomOS has **no** label table — `mapAdditionalLimits` rendered `limit_name` verbatim, and those strings ARE what OpenAI's endpoint returns on `plan_type: "prolite"`. The plan's structure also changed: the headline `rate_limit` is weekly-only (no 5h secondary), Spark carries its own 5h+7d pair, `gpt-reserve` a 7d only, and `credits.balance` now arrives as the string `"0"`. `gpt-reserve` is what the Codex CLI calls **Luna Reserve** (`LUNA_RESERVE_MODEL` in `codex-rs/tui/src/model_catalog.rs`, added in rust-v0.154.0 #42372): a fallback allowance of GPT-5.6 Luna that Codex routes to once ordinary usage is exhausted (`normal_model_slug: "gpt-5.6-luna"`). The CLI's `/status` relabels only that one; Spark shows under its model name. codexbar names Spark "Codex Spark 5-hour/Weekly", leaves `gpt-reserve` raw, and maps `prolite` → "Pro 5x" / `pro` → "Pro 20x".
- **Decision:** (1) **Known lanes say what `codex /status` says** — `gpt-reserve` → "Luna Reserve"; Spark keeps its model name — with a one-line explainer under each (the reserve's names its fallback model from `normal_model_slug`, so a future reserve model relabels itself). The table lives server-side (`plugins/codex-usage/limitLabels.ts`) so the usage queue's cap labels and the dashboard agree. (2) **An unknown NAME never drops a lane** (the only thing that skips a lane is having no renderable window at all): any `limit_name` the API sends tomorrow renders lightly prettified (an all-lowercase machine slug is word-split and capitalized, an author-cased name passes through verbatim) with the generic explainer "Additional usage lane"; both panel and status-bar labels are single-line with ellipsis + full text in `title`, so a long name cannot break layout. Duplicate ids get a numeric suffix rather than dropping the later entry. Pinned by tests with an invented `limit_name`. (3) Plan pill uses codexbar's marketing names for the Pro tiers; an unknown plan id renders word-split ("free_workspace" → "Free Workspace"), never hidden. (4) Credit balances parse from numeric strings. The weekly upstream codexbar check is the cue to add friendly labels when new names appear — the bar is correct-if-unlabeled in the meantime.
- **Rationale:** Matching the CLI means the dashboard uses the words Terry already sees inside `codex`, and it needs exactly one alias rather than a growing per-model list (codexbar's "Codex Spark" would be a second naming scheme for the same lane). The open-ended `additionalLimits` design (types.ts header) already made new lanes surface automatically; this keeps that property and only fixes the presentation. Terry's own words set the bar: "matching labels is fine but if new things come in we should still support."
- **Alternatives considered:** B — friendly names for both lanes (codexbar's "Codex Spark" + "Luna Reserve"): rejected, two naming schemes and a hand-kept alias per model. C — raw names + explainers only: rejected, diverges from what the CLI shows for the reserve. Mapping in the dashboard instead of the server: rejected, the usage queue's cap label would still say `gpt-reserve`.
- **Not done (follow-up):** the rollout FALLBACK (`scanner.ts fromRollout`) hardcodes `additionalLimits: []`, so an endpoint outage silently drops the Spark/Reserve rows. Terry's newest on-disk rollout predates the plan change, so the new rollout shape cannot be verified against real data yet; separate PR once a post-upgrade rollout exists.
- **Source:** TeamLead@autonomOS relay of Terry's pick (2026-09-12); mockup artifact 5fb9bff1; investigation in this PR.
