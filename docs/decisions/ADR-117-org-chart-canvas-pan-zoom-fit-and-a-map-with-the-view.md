## ADR-117: Org chart canvas: pan, zoom, fit and a map, with the view outside React state

- **Date:** 2026-09-26
- **Decided by:** Terry (picked all four recommendations on the interactive mockup, relayed by TeamLead: "go with all your recommendations"), built by OrgChart@autonomOS.
- **Context:** The Org Chart was a fixed-size stage inside a native scroll container. A real fleet (20+ agents, teams side by side) is several thousand pixels wide, so most of it sat off-screen with no overview and no way to zoom out. Terry asked for "a map at the bottom right, and I can drag around the page". The #425 rule had to survive: a click on empty canvas never closes the inspector.
- **Decision:**
  1. **Gestures.** Drag EMPTY canvas to pan; a press that moves less than 4 px is a click, and a click on empty canvas does nothing. A drag that starts on a card, button or bubble never pans (PR 4 will give card drags a meaning, reassign, so they stay inert until then). Two-finger scroll pans; a pinch (ctrl + wheel in Chromium/Firefox, gesture events in Safari) or ⌘ + scroll zooms at the pointer, 30%–200% (pick 1A). Touch: one finger pans, two pinch. Keys while the chart has focus: F fit, 0 = 100%, + / − zoom; modified keys are left alone.
  2. **Opening view: fit, but never below 60%** (pick 4A). A big org opens readable at the top of the tree; Fit still shows everyone (down to 30%). Mockup testing changed this from plain "fit everyone", which put a 24-agent fleet at ~30%.
  3. **A bottom-right map, shown only when the chart doesn't fit** (pick 2A): every card in its status color (the same `rollupBucket` the rollup chips use) plus the viewport outline; click or drag it to move. SVG, not canvas, so it is testable.
  4. **Message bubbles counter-scale** so their text stays readable at any zoom (pick 3A), through a `--org-inv-k` variable on the stage and the independent `scale` property (it composes with the unfurl animation's `transform` and pivots on the bubble's tail).
  5. **The view lives outside React state.** `useCanvasView` keeps `{x, y, k}` in a small store, writes the stage transform straight to the DOM, and re-renders only its subscribers (the zoom %, the map). All the math is pure functions in `orgchart/viewport.ts`.
  6. The arrow-key walk pans just enough to keep the selection on screen; a pan or zoom closes an open context menu; the view is never moved when agents come or go.
- **Rationale:** a pan fires a pointermove every frame; re-rendering every card for each would make a large fleet stutter, and the chart is exactly where fleets get large. Scroll-to-pan matches a Mac trackpad (Terry's machine) and Figma; scroll-to-zoom punishes a trackpad flick. Keeping card drags inert avoids changing their meaning twice when PR 4 lands. The hero script now presses the product's own Fit button instead of overwriting the stage transform.
- **Alternatives considered:** keeping native scrolling plus a CSS `zoom` (no zoom-at-pointer, and `zoom` breaks pointer maths); a canvas library (react-zoom-pan-pinch and similar: a dependency for ~200 lines of tested math, and it would own the pointer events the #425 click rule depends on); scroll-to-zoom (pick 1B); an always-visible map (2B); remembering the last view (4B, a stale view is confusing when the fleet has changed).
