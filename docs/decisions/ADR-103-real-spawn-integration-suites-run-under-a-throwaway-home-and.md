## ADR-103: Real-spawn integration suites run under a throwaway HOME, and are safe to run locally

- **Date:** 2026-09-24 · **Decided by:** Terry (via TeamLead: fix the leak, audit isolation + cost, recommend A/B); Claude (audit + implementation)
- **Context:** The `AUTONOMOS_INTEGRATION=1` suites spawn a real `claude`. The harness isolated the server's config dir but inherited the operator's HOME, so every run (1) wrote a session dir into the real `~/.claude/projects` (visible in the dashboard's Projects panel as `autonomos-usageq-cwd-*` / `autonomos-prompt-cwd-*`) and (2) had the spawn-time pre-trust write a `projects[<tmp cwd>]` entry into the real `~/.claude.json`. Terry also recalled local test runs damaging the live install. That history is `test-install.sh` / launchctl label collisions, which stay CI-only regardless. He asked for proof that these suites share none of it, plus their cost.
- **Decision:** Every `bootServer()` runs under a throwaway `HOME`, `CLAUDE_CONFIG_DIR` (seeded with CI's onboarding config) and `CODEX_HOME` inside its own config dir, and sets `AUTONOMOS_DISABLE_CREDENTIAL_READS=1` plus `DISABLE_TELEMETRY` / `DISABLE_ERROR_REPORTING` / `DISABLE_AUTOUPDATER`. Every booting suite ends with a real test that fails if anything new under a temp-dir cwd appeared in the operator's real `~/.claude/projects` or `~/.claude.json` since boot. The usage plugin's `resolveToken()` honors `AUTONOMOS_DISABLE_CREDENTIAL_READS=1` by reading no store (after the explicit env-token check, before the async keychain read added by #384): its keychain lookup is keyed on `$USER`, not HOME, so a fake HOME alone would not isolate it. **Verdict (A):** the suites are safe to run locally next to a live deployment. The comments in `test.yml` and the harness say so. `test-install.sh` and the service verbs stay CI-only.
- **Audit evidence (2026-09-24, macOS, claude 2.1.281, live :3100 running):**
  - *Paths:* config dir, control socket and pid file are all under the per-boot temp dir. Token: `AUTONOMOS_TOKEN` is set, so the real `~/.autonomos/token` is never read (and the legacy fallback now resolves inside the fake HOME). Spawned agents show `HOME`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` at the fake paths (env sampled every 0.2s). Before/after snapshots of the real `~/.claude/projects`, `~/.claude.json` trust keys, `~/.autonomos/agents`, `launchctl` and the :3100 listener PID/start time were unchanged. Mtime changes on `~/.claude.json` and `~/.codex/logs_2.sqlite-wal` were shown to be the live fleet: both kept changing with no test running, and `lsof` showed live `codex` PIDs writing the WAL.
  - *Credentials:* under the harness env, `claude auth status` reports `loggedIn: false, authMethod: none` (a relocated `CLAUDE_CONFIG_DIR` uses its own keychain entry), and 0 `security find-generic-password` processes were observed. Model turns go only to the local mock (`ANTHROPIC_BASE_URL`), so billed API spend is 0. The remaining ~14 outbound TLS connections per run are unauthenticated startup calls from a logged-out CLI.
  - *Processes:* the server's only signal sites target its own PTYs, sidecar, or `kill(pid, 0)` (a liveness probe, no signal). The harness SIGTERMs only its own child. No suite or server path runs `pkill`, `launchctl`, `systemctl` or `pm2` (those appear only in comments). The public listener uses `--port=0`, and the CLI flag outranks `PORT`, so 3100 is unreachable.
  - *Cost (6 active suites, 30 tests):* 34s wall, peak 6 concurrent `claude`, peak CPU ~90–147%, mean ~8–12%, peak RSS ~1.35 GB.
  - *Mutation-verified:* removing the HOME override (run with a sandbox as the "operator home") fails the leak test with exit 1, naming the project dir and trust key. Removing the credential guard fails its unit test. An earlier version asserted in `after()`: node's runner reports a failing `after()` as `not ok` but exits 0, so that check could not fail CI. It is a real `it()` now.
- **Alternatives considered:** **(B) keep CI-only:** rejected. The audit found nothing shared with the live install, and CI-only meant regressions surfaced only after push (see the babysit lesson). **`CLAUDE_CODE_OAUTH_TOKEN=<dummy>` to bypass the keychain:** rejected, because the spawned `claude` also reads it and would believe it is logged in. **`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`:** ineffective, because the provider strips every `CLAUDE_CODE_*` var from agent envs.
- **Not in scope:** deleting the already-leaked real `~/.claude/projects` entries (Terry's data, handled separately); the quarantined `usage-queue-sim-integration` (skip: true) inherits the isolation when it is un-quarantined.
- **Source:** TeamLead relaying Terry over the autonomOS agent channel, 2026-09-24.
