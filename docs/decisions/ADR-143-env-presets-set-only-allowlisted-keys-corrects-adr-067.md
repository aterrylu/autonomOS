## ADR-143: Env presets set only allowlisted keys (corrects ADR-067)

- **Date:** 2026-10-01
- **Decided by:** TeamLead@autonomOS (ruled option A of the V13 proposal), implemented by SecurityFix-Hardening@autonomOS (agent)
- **Supersedes:** ADR-067 (its guarantee that a preset can't run code in another agent's process; the rest of ADR-067 stands)
- **Context:** Security audit V13. ADR-067 claimed, and `envPresets.ts` said, that a denylist (`LD_PRELOAD`, `LD_LIBRARY_PATH`, `LD_AUDIT`, `DYLD_*`, `NODE_OPTIONS`, `BUN_INSPECT`) stopped a preset from running code inside a sibling agent's process. That guarantee was false. `createEnvPreset` and the spawn path accepted and injected `BASH_ENV`, `ZDOTDIR`, `SHELL`, `CLAUDE_CODE_SHELL_PREFIX`, `CLAUDE_CONFIG_DIR`, `GEMINI_CLI_SYSTEM_SETTINGS_PATH`, `GIT_SSH_COMMAND`, `GIT_CONFIG_GLOBAL`, `BUN_OPTIONS` and more. Each of them either runs code in the agent's shell or tool calls, or redirects its config and credentials. A denylist of environment variables can't be complete: every CLI the agents run reads its own.
- **Decision:** (1) A preset may set ONLY the keys in `PRESET_ALLOWED_ENV_KEYS`: the variables that choose a model backend (model, endpoint and auth for Claude Code and Anthropic-compatible backends such as Kimi/Moonshot, Bedrock/Vertex, Codex and Gemini), plus proxy (`HTTP(S)_PROXY`, `NO_PROXY` and the lowercase forms) and CA trust (`NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`). A control-plane key (`RESERVED_ENV_KEYS`) is never allowed, even if a future edit lists it. (2) Creating a preset, or an edit that supplies env, secretKeys or a real secret value, is refused for any other key with a typed `PresetKeyError` (HTTP 400). The message lists what is allowed. (3) Migration: a preset saved before this still loads and spawns. Its off-list keys are SKIPPED at injection, never applied, and the operator gets a notice naming them, queued with the spawn's other notices and logged. An off-list secret with no value doesn't block the spawn. Editing a legacy preset still works: a description change, or the dashboard's masked round-trip, sets nothing new and isn't refused. (4) The proxy and CA variables can route an agent's traffic through an interceptor. Setting them is an explicit operator choice under ADR-067's trusted-fleet model, and is allowed because a corporate network needs them to reach any backend.
- **Rationale:** An allowlist is complete by construction, and it matches what a preset is for: pointing an agent at another model backend. Everything else a preset could set was capability nobody asked for. Adding a backend's variable is one line, reviewed like any other change. Skipping instead of refusing at spawn keeps an upgrade from stranding agents built on an old preset, while the notice makes sure the skip isn't silent. What the allowlist does NOT mean: a preset can still direct where an agent's model traffic goes and what it trusts. The `*_BASE_URL` keys choose the endpoint that receives the credentials, the proxy keys route the traffic, and the CA-trust keys decide which certificates the agent accepts. So a preset can still redirect the very credentials it carries. That is the capability ADR-067 already accepts under its trusted-fleet model; this ADR closes code execution and config redirection, not credential redirection. This does NOT change ADR-067's honesty caveat: under the trusted-fleet model, an agent that can spawn with a preset can still read its key from the child's env or repoint `ANTHROPIC_BASE_URL`.
- **Alternatives considered:** Extend the denylist with the audit's keys: refused, because it would be incomplete again with the next CLI release. Refuse a legacy preset at spawn: refused, because an upgrade would then strand every agent using an old preset until a human edited it; skipping with a notice is the ruling. Only correct ADR-067's wording and keep accepting any key: refused, as the weaker of the two options the audit offered. Per-provider allowlists (only `ANTHROPIC_*` for Claude Code, and so on): deferred. One shared list is simpler, and a key for another runtime is inert in a process that doesn't read it.
- **Source:** Security audit P1 finding V13; TeamLead@autonomOS agent channel, 2026-10-01 ("V13 RULED: option (A) a strict env-preset ALLOWLIST … + proxy vars … + CA trust … Migration: existing presets load, unknown keys are SKIPPED at injection with a loud notice naming them; new presets REJECT them").
