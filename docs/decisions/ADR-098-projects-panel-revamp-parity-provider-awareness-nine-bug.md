## ADR-098: Projects panel revamp — parity, provider awareness, nine bug fixes

- **Date:** 2026-09-10 · **Decided by:** Terry (picks A/B/C + bundle greenlight via TeamLead); Claude (implementation)
- **Context:** The Projects panel (`ProjectItem` in `Sidebar.tsx`) rendered a visibly poorer version of the live agent rows sitting right above it — a 6px colored dot instead of the `ProviderAgentIcon` the live rows already render, hard-coded hex instead of theme tokens, `text-[10px]` metadata — and could only ever show Claude Code sessions (the listing is sourced from the SDK's `listSessions()`, i.e. `~/.claude` only). Terry: "it currently looks really ugly, also it only includes claude code sessions, not Codex. Improve both UIUX, fix bugs if there are." A [mockup round](https://claude.ai/code/artifact/ea77d35e-8c2e-49d6-b336-4d6f9fde7123) put three calls to him.
- **Decision:** Promote the row to **parity** with the live `SessionRow`, in a distinct "archive" treatment, and make it provider-aware. Terry's picks: **A = distinct archive look** (the shared vocabulary but quieter — dormant history shouldn't compete with the live fleet); **B = minimal+ header** (a `projects·sessions` count + a collapse-all control + expand state moved into the store so it survives the Sidebar's unmount-on-collapse — the old bug #8 — and persists across reloads); **C = show our own sessions as subordinate jump-to-live chips** (Terry overrode the hide recommendation: an autonomOS-spawned running session renders as a quiet "Live ↗" chip that jumps to the pane, while external sessions stay the adoptable "Resume" stars). The row is a three-column grid — provider glyph · resolved title + `cwd·branch` · status pill — with three states: `live` (ours+running, jump chip), `stopped` (ours+exited, resume-with-config), `external` (unmanaged, the adoptable Resume). A codex row slots in with no special layout because the icon primitive already knows codex/gemini — so this UI and CodexGemini's discovery backend ship as **one bundle** at Terry's visual gate.
- **Wire model:** `ProjectSession` gains a `provider` field (drives the glyph) and an optional `originator` (codex origin classification); the misleadingly-named `customTitle` wire field is **removed** — it duplicated the resolved title `summary` already carries and was named for a value it never held (bug #4; the semantic-rename rule says a meaning change is a name change, and here the honest move was deletion). `projects.ts` sets `provider:"claude-code"` on CC rows and exposes a `listCodexSessions()` seam (owned by CodexGemini's PR) that merges codex rows (in the shared shape) into their cwd group.
- **Nine bugs fixed:** #1 CC-only (the revamp + the seam); #2 the "+" quick-spawn now spawns in the project's own provider (it always created a Claude agent); #3 row state is consistent (external → Resume, not a mislabeled "exited"); #4 the `customTitle` wire field removed; #5/#6 a managed row's age reads the live record's `lastActivityAt` (3s, hook-driven) rather than the 30s projects-poll file mtime that lagged and disagreed with the live dot; #7 cwd-less sessions are keyed per session (`unknown:<id>`) so unrelated ones don't merge; #8 expand state persisted in the store; #9 no empty project name.
- **Rationale:** The redesign isn't inventing a look — it borrows the live row's own vocabulary, which is why it also makes the Codex row a data-plumbing story rather than a visual-design one. Distinct-archive keeps Projects legible as "adoptable history" next to the live fleet. Moving expand to the store is the only correct fix for a panel whose component unmounts on collapse.
- **Alternatives considered:** mirror the live rows exactly (rejected at A — dormant history shouldn't shout as loud as running agents); full header controls with sort + provider filter (deferred at B — sort is already recent-first and a filter earns its place only once codex/gemini rows are common); hide our own sessions (Terry overrode to jump-to-live chips at C); renaming `customTitle`→`resolvedTitle` (rejected for deletion — `summary` already carries it, a rename would just add a redundant field).
- **Correction (2026-09-11) — the "distinct archive" look (A) was TRIED and REVERSED at the visual gate.** Terry saw the built archive treatment and rejected it, then (after a styling-variants artifact round) picked the opposite: *"I actually want it to retain as much styling and sizing as possible as the Agents tab agent UI."* So the row now **mirrors `SessionRow`** rather than being quieter than it — the archive-distinct decision above (the `A` framing, the row/icon opacity dimming at `0.72`/`0.82`/`0.6`, the muted `statusFg` name color, and the rounded-full status pills) is **superseded**. `ProjectItem` now uses the exact `SessionRow` box (`gap-1.5`, `py-1`, `ProviderAgentIcon size={16}` bare, `flex-1 min-w-0` two-line anatomy with **age on the name line** and a trailing status slot on line 2) with **no dimming anywhere**. Only the minimal function deltas remain, and they live in that same trailing slot SessionRow uses for its status label — a subtle `↗` jump hint (live, `role="img"` labelled), a plain "Stopped" label, or a hover-revealed "Resume" (external, theme accent). Decision **B** (header + store-persisted expand) and **C** (our-sessions-jump-vs-external-resume behavior) stand; only the archive **visual** framing of **A** is reversed. Verified via the full suite (564) + Terry's live :5411 gate. `make hero` still owed at merge (panel is hero-visible).
- **Refinement (2026-09-13) — state differentiation returns, SELECTIVELY.** After seeing the fully-flat parity look, Terry: *"I want the archived/killed agents to be kinda GRAYED OUT; the live ones should reflect the same STATUS (green instead of empty circle)."* So the anatomy/sizing parity stands, but the dead-row dimming comes back for **dead rows only** — the earlier archive instinct was right for *those* rows; the reversal was about anatomy, not about dead things looking dead. Two changes: (1) a **LIVE** row reads its real fine-grained status from the SAME `agentStatuses` feed the Agents-tab rows use (`GET /api/agent-status`), so `ProviderAgentIcon` shows the real corner dot (green idle / blue working / amber needs-input) instead of the blank circle the coarse record `status:"running"` produced — cast through `as AgentStatus` exactly like `SessionRow` (the prop type is coarse but `statusCategory()` reads the fine runtime value); (2) **DEAD** rows (stopped/external) are grayed via `opacity-60` on the row, `transition-opacity hover:opacity-100` so the Resume affordance stays legible on hover. Live rows are full-strength. Same skeleton for both. Verified on :5411 (live rows show green dots + ↗, dead rows dimmed) and unit-tested (`ProjectItem.dom.test.tsx`: dead rows carry `opacity-60`, live rows don't).
- **Disclosure + header, 2026-09-13.** A [disclosure options artifact](https://claude.ai/code/artifact/714712b7-1dbc-4a79-9d14-908844096cb0) (6 affordance × 4 mechanism variants on the real panel, both themes, my rec) went to Terry; he LOCKED **A = rotating chevron, B = accordion**. Built: (1) the project-group disclosure is a **rotating chevron** (base SVG points right, CSS `rotate(90deg)` + `transition-transform` on expand) replacing the tiny ▾/▸ glyph-swap; (2) `toggleProjectExpanded` is now an **accordion** — `expandedProjects` holds 0-or-1 `true` entry (opening one clears the rest), so at most one project's sessions occupy the sidebar height (store test in `store.test.ts`). Also **removed the projects·sessions header count** ("16·53") at Terry's request — the per-project row count + collapse-all stay. The **AGENTS-section header** (the empty space by the New-agent affordance) is a SEPARATE options round / likely its own small PR — flagged interplay with the digit-badge hold-hints (ADR-066) and the Onboarding bottom-rail card slot.
- **Live gate, 2026-09-24 — chevron reverted.** On `:5411` Terry rejected the rotating SVG chevron (pick A): "I don't like the new chevron icon to the left. Please revert to the older chevron icon styling." The pre-#369 disclosure is restored exactly: a `text-[10px]` span in `page.statusFg` that swaps `▶` (collapsed) / `▼` (expanded), no rotation or transition. The accordion (pick B), the right-edge V1 slot, and everything else in this ADR stay. A dom test pins the glyphs so the styling can't drift again.
