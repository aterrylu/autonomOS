## ADR-135: Reconnect replay restores terminal state: sticky modes, PTY geometry, repaint nudge

- **Date:** 2026-10-01
- **Decided by:** Terry (via TeamLead: "GO with 2 + 3 now", option 1 deferred to a perf measurement); implemented by TerminalRender (agent)
- **Context:** Terry hit two terminal bugs on main: (A) individual Codex panes froze and could not be scrolled; (B) a Claude Code pane with `CLAUDE_CODE_NO_FLICKER=1` went black except the regions that repainted. Both reproduced on an isolated rig with real agents and traced to the reconnect replay. Every terminal socket open resets the pane's xterm and the server replays its output buffer, the last 1MB of raw PTY bytes, trimmed from the front in whole chunks. Both CLIs are full-screen TUIs on the alternate screen that set their modes ONCE at startup and then diff-draw (Codex 0.154: `?1049h` at byte 69, `?1007h` alternate scroll at byte 89; Claude no_flicker: `?1049h` + mouse tracking `?1000/1002/1003/1006h`). (A): once a session passes 1MB the trim drops `?1007h`; after the reset the wheel does nothing (the alternate screen has no scrollback and no arrow keys are sent). Proven with the same real Codex stream replayed whole (wheel → `\e[A`) vs head-trimmed (10 wheel ticks → 0 bytes). (B): a FRESH pane (page load, or re-created after the LRU cap of 8 evicted it) received the replay at xterm's default 80x24 before its first fit; the alternate screen never reflows, so the content landed in an 80-column strip and the rest stayed black. Nothing repaired it: the PTY was already at the right size, and a same-size TIOCSWINSZ sends no SIGWINCH (measured on macOS), so the TUI never redrew. WebGL was ruled out (forced context loss with and without restore repainted correctly). #397 made it frequent: it added reconnect triggers, including cutting every pane whenever the `/ws/agents` heartbeat went stale for 5s on a busy server.
- **Decision:** (1) The server tracks the sticky DEC private modes (`agents/terminalModes.ts`: alternate screen 47/1047/1049, mouse 1000–1006/1015, focus 1004, alternate scroll 1007, bracketed paste 2004, cursor keys 1, cursor visible 25; RIS resets) with two trackers per attachment: `live` follows every chunk, `head` consumes each chunk the 1MB trim drops. A replay is `head.preamble()` + the retained bytes, which ends in exactly the live state. The preamble is plain escape sequences, so it is sent to every client. (2) For clients that ask (`?replayGeom=1`) the server sends `OSC 7777;autonomos-replay-begin;cols=C;rows=R` BEFORE the replay; the pane resizes xterm to the PTY's size first, keeps its reply-suppression window open, and re-fits to the pane after the end marker (a real size change, so the TUI gets SIGWINCH and repaints). (3) When the buffer has been trimmed and the live state is the alternate screen, the server nudges a repaint after the replay: a REAL size change and back (rows−1, restored after 60ms unless a client resized in between), rate-limited to once per 2s per PTY. (4) In acked-input mode a stale status heartbeat no longer cuts panes; per-keystroke acks already detect a dead pane socket within 1s, and every cut was a full reset + replay.
- **Rationale:** The replay was a log, not a state: any mode a TUI sets once is lost to a trim or a reset, and any replay parsed at the wrong size is permanently wrong on the alternate screen. Tracking only `ESC [ ?` sequences (located with indexOf) is cheap enough to run on every byte for 30–50 agents, which today's load (avg 500–660 during the incident) argued for over parsing everything. Feeding the head tracker the dropped chunks makes the replay exact without remembering any history beyond the retained buffer. The geometry marker rides the existing OSC 7777 channel and is opt-in, so an older dashboard never sees it; the repaint nudge reuses the reconnect-only exception ADR-087 already allows (an alternate screen has no scrollback for ratatui's `\e[3J` to wipe).
- **Alternatives considered:** A headless xterm per session (`@xterm/headless` + `addon-serialize`, both available for xterm 6) sending a serialized snapshot: the most robust (restores everything, including static alternate-screen content without a repaint), but parses every byte of output server-side for every agent; deferred until it is measured on the perf harness. Re-sending the same size to force a repaint: a no-op (no SIGWINCH). Nudging a repaint on every reconnect: unnecessary when nothing was trimmed (the replay holds the original paint) and it would perturb normal-buffer TUIs (ADR-087). Keeping the transport-stale cut for acked panes: it is what turned a busy server into a replay storm. Bigger buffer: postpones the trim, doesn't remove it, and costs memory per agent.
