## ADR-157: The ADR index is not committed; the index and collision bots are removed

- **Date:** 2026-10-29
- **Decided by:** Terry ("bots: remove", option A of the options sheet), relayed by TeamLead@autonomOS; options sheet and implementation by Decisions@autonomOS.
- **Context:** ADR-114 committed a generated index table (`docs/decisions/README.md`). PRs never edited it, so it couldn't become the per-PR conflict hotspot the per-file layout removed. A workflow therefore regenerated it after merges (hourly since ADR-147) and delivered it as a rolling bot PR. ADR-150 added a second job to that workflow: when two PRs both merged the same ADR number, it opened a PR renumbering the later one. In practice the index PR needed an approval that nox never gave (#499 was opened 2026-10-01 and never merged, so by 2026-10-29 the committed table was four weeks stale; it is closed along with the workflow). The renumber bot never fired once. Terry, reviewing it: "I don't know how it works or when it was created, very strange mechanism, don't know if we need it."
- **Decision:**
  1. `.github/workflows/decisions-index.yml` is deleted, and with it both jobs: the hourly index regeneration and the collision renumber.
  2. `docs/decisions/README.md` is a hand-written static guide, edited like any doc. No index table is committed anywhere. GitHub's folder view lists every ADR by number and title (the filename), and `make adr-index` prints the full table (date, status, supersession) from the files.
  3. Kept as they were: `make adr` (number allocation across main and open PRs), `make adr-renumber`, `make adr-import`, and the CI check in `make check`. It still fails a PR, and main's own CI on push, on a duplicate number, a missing field, or an edited legacy entry.
  4. A duplicate that reaches main is fixed by a human: main's CI goes red with the renumber command, and whoever merged later runs `make adr-renumber` in a follow-up PR.
- **Rationale:** The committed table was informational: nothing reads it at build or run time, and every ADR carries its own status and links. Keeping it fresh cost a bot, an approval per refresh, and a mechanism the owner didn't trust. Without a committed table there's nothing to regenerate and nothing to conflict on. Collisions stay caught: the PR-time check catches most, and since ADR-149 main runs CI on every push, so one that slips through is loud. The fix is one command touching one file, so a bot isn't worth its complexity for an event that hasn't happened.
- **Alternatives considered:** Keep both bots (needs a human approval on every index PR, plus a mechanism Terry has to trust). Have each ADR PR regenerate the committed table (every ADR PR edits the same rows, so two open ADR PRs conflict, and a conflicted PR runs no CI until rebased: the hotspot ADR-114 removed). Give the bot a ruleset bypass (a bypass can't be scoped to one file; it exempts the actor from the whole ruleset, so a leaked key could push anything to main). Keep only the collision bot (it has never fired, and main's CI already makes a collision loud).
- **Supersedes:** ADR-147 and ADR-150, and part of ADR-114 (decision 5, the committed generated index and its post-merge regeneration). ADR-114's per-file layout, check and allocator stand.
- **Source:** autonomOS agent channel, 2026-10-29: TeamLead's status sweep for Terry, Decisions@'s options sheet, Terry's "bots: remove"; the PR that removed the workflow.
