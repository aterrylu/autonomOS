## ADR-108: Agent-to-agent messages on the Org Chart — a preview-only broadcast, full text on demand

- **Date:** 2026-09-24 · **Decided by:** Terry (asked for a *fun* way to see the text moving from agent A to agent B; picked the Envelope style and the on-demand full text), designed + built by OrgChart@autonomOS, relayed via TeamLead.
- **Context:** The gateway was stateless about traffic by design (ADR-064 answers "was it accepted?", nothing more), so the dashboard couldn't show who talks to whom. The Org Chart's message flow and its inspector's Communication section both need a per-message signal and some per-agent history, without turning message text into something every dashboard receives or that persists.
- **Decision:**
  1. **One recorder at every accept point.** `gateway/messageLog.ts` `recordAcceptedMessage` is called ONLY after a destination accepted: the Codex `turn/start` reply, the manual-queue enqueue (queued = accepted per ADR-064), and the Claude Code open-socket write. It's never called on a failure path, so the chart can't show traffic that didn't happen. It never throws; recording can't turn a delivered message into an error.
  2. **The broadcast carries a preview only.** A new `message.routed` `AgentDelta` on the existing authenticated `/ws/agents` channel carries `{id, from, fromName, to, toName, preview, ts}`. The `preview` is sanitized server-side (ANSI/OSC escapes, control characters and markdown syntax stripped, one line) and capped at 60 code points (surrogate-safe). `from` is null for a non-agent sender (a schedule).
  3. **Full text is on demand, per agent.** A 50-message in-memory ring buffer per agent (text sanitized and capped at 400) plus sent/received/per-peer counters, read via `GET /api/agents/:id/messages`. It's lost on restart and dropped on hard delete. Full text is never pushed.
  4. **Client rules.** Everything renders as text (React children, never HTML). Bursts coalesce into one bubble per recipient with "+N" and the NEWEST line by arrival order. At most 3 envelopes fly at once. Quiet / Off / prefers-reduced-motion all mean no travel. A message to an agent folded away lands on its nearest visible ancestor. **Every envelope has a timer backstop, and nothing animates into a hidden tab:** measured live, browsers pause `requestAnimationFrame` in background tabs, so envelopes hung mid-edge forever and pinned the in-flight cap.
- **Known gap (accepted):** a Codex message that misses the 2s ack window but lands later on the transport-retry path isn't recorded, because that path doesn't return through `routeToAgent`. The chart under-reports rather than showing traffic that may not have happened. It's recorded here so it isn't mistaken for a bug in the accept-point rule.
- **Sanitizing runs on the event loop, so it's bounded:** the input is cut to 10× the display cap before any regex runs, every pattern is linear (bounded quantifiers; nothing spans newlines), and the text is sanitized once per message. Found in review: unbounded patterns took 4–15s on 100k-character hostile or malformed input, which would have stalled every PTY and socket on the server. A timing test pins it (and fails at ~16s without the fix).
- **Rationale:** the preview is the fun; the full text is useful but private-ish, so it stays one authenticated, per-agent read away instead of fanning out to every open dashboard. Counting at the accept point (not at send time) keeps the chart as honest as ADR-064's delivery acknowledgement.
- **Alternatives considered:** **Full text on the socket** (the first mockup) was rejected: every dashboard would receive every message. **Persisting the log to disk** was rejected: it's more surface (retention, redaction) for a chart feature; memory is enough. **Counting at send time** was rejected: it would show messages that were refused. **Client-side sanitizing only** was rejected: the cap and strip must happen before the text leaves the server.
