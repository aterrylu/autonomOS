## ADR-161: A pane resizes xterm only together with the PTY

- **Date:** 2026-11-22
- **Decided by:** TerminalRender@autonomOS (agent), as a bugfix under Terry's standing rule that bugfixes merge without his sign-off; assigned by TeamLead.
- **Context:** Terry reported that after switching panels, a terminal often showed its bottom half at the top and the rest at the bottom, and only a hard refresh fixed it. The cause is in `LiveTerminal.applyFit` (`liveTerminals.ts`). It could resize xterm without the PTY following, in two ways:
  - The focus gate from #125 (only the focused window sends its size, so two dashboard windows don't fight over the PTY's one size) skipped only the SEND. `fitAddon.fit()` had already resized xterm, so an unfocused window resized its terminal on its own.
  - `fit()` ran before the plausibility check, so a rejected size (an unsettled renderer) had already resized xterm too.

  On a normal-buffer TUI that's reversible: xterm reflows the scrollback. The alternate screen (Claude Code's no_flicker, `?1049h`) has no scrollback and doesn't reflow. A shrink drops the top rows, and growing back adds blank rows at the bottom. The PTY never changed size, so the agent got no SIGWINCH, and Claude's differential renderer only rewrites cells it believes changed. The screen stayed shifted. A later switch or refocus re-sent the PTY's SAME size, which isn't a SIGWINCH either. #125 had covered this with a focus-regain resize nudge, which ADR-087 removed (it wiped Codex's scrollback). Measured on an isolated instance with a real Claude Code TUI: an unfocused 49→34→49-row box change resized xterm both ways with 0 resize messages sent, leaving the prompt at row 33 of 49 with the status block gone, until a reload. A real PTY size change healed it.
- **Decision:** xterm's size changes only together with the PTY's.
  - `applyFit` reads `fitAddon.proposeDimensions()` and checks plausibility BEFORE `fit()`, so a rejected size never reaches xterm.
  - While `document.hasFocus()` is false, the whole fit waits: xterm keeps the size it last fitted while focused, and the existing `handleFocus` re-fits and sends on return. The #125 protection is unchanged: an unfocused window still never sends its size. The client-only settle refresh after a WebGL recreate still runs (it sends nothing to the PTY), so a background window that loses its GL context doesn't keep stale rows.
  - A focused fit with no OPEN socket still applies, and the send is a no-op. That gap closes on the reconnect: the server always sends the PTY's size first (the ADR-135 replay-begin marker), the pane parses the replay at it, and the end marker re-fits and sends.
  - No fake resizes anywhere (ADR-087 stands).
- **Rationale:** The fix sits at the one boundary every fit goes through: the ResizeObserver, attach, focus, the replay end, and WebGL recreate all call `applyFit`. In the single-window case the PTY's size is the size the pane last fitted, so an unfocused window keeps showing the agent's real screen (clipped or padded if its box changed) instead of a corrupted one. **Known limit:** a second dashboard window in the background isn't told when the focused window resizes the PTY (live resizes carry no geometry), so it can still show an alternate-screen agent at the wrong size until it is focused or reconnects. The fix only stops it from adding damage of its own with a local resize.
- **Alternatives considered:**
  - Send the resize even when unfocused: that reopens #125, where a background window shrinks the PTY under the focused one.
  - A repaint nudge on focus regain (#125's original design): ADR-087 removed it because Codex rebuilds with `\e[3J` on every SIGWINCH and the nudge wiped its scrollback.
  - Repairing the screen client-side after a local resize (a cold replay or `reset()`): it re-streams up to 1MB, the keep-alive cache's whole point (ADR-072) is to never do that, and it treats the symptom.
  - Fixing it in xterm's alternate-buffer resize: the loss is inherent (no scrollback to reflow into), and the TUI still wouldn't know.
- **Source:** TeamLead relay of Terry's report, 2026-11-22. Fix PR `terry/terminal-switch-rotated-rows`. Guards in `liveTerminals.dom.test.ts`, describe "pane size never diverges from the PTY" (4 tests red with the fix reverted, including the #125 multi-window case, plus a focused-path pin), and "an UNFOCUSED window still gets the settled refresh after a context loss" in the WebGL-recreate describe.
