## ADR-134: Shutdown survives a closed stdout and uncaught errors

- **Date:** 2026-09-30
- **Decided by:** TeamLead (agent), approving CodexGemini's (agent) proposal after a measured repro
- **Context:** Running the server as `server | tee` and pressing Ctrl-C signals the whole pipeline, so tee dies alongside the server. On macOS a write to a closed pipe fails asynchronously, as an `'error'` event on `process.stdout`. The server had no listener, so the first log line after the reader went away was an uncaught exception. Sometimes that was the shutdown handler's own "Shutting down…" line; sometimes a routine log line before any signal. The group SIGHUP (sent synchronously) went out, but the process died before the timed stages ran: the PTY SIGTERM (250ms) and SIGKILL (2s), the sidecar daemons' forced second SIGTERM, and the bounded daemon wait. Measured on an isolated instance with a busy Codex agent: in two of two runs, the `codex app-server` daemon survived, reparented to init, with the agent's running shell command and MCP servers under it. Gemini survived nothing in any run, because the group SIGHUP alone ends it.
- **Decision:** (1) The logger installs one `'error'` listener on stdout and stderr, before it tries file logging. EPIPE (or a destroyed stream) marks that sink broken and nothing more is echoed to it; the rotating file keeps every line. Any other stream error still throws. (2) The shutdown handler's first act on the first signal is to arm process-level `uncaughtException`/`unhandledRejection` handlers. From then on an error is logged (the first 5 in full) and swallowed, and the stages and the bounded daemon wait still finish and still end in `exitProcess`. The first log line is itself guarded. Outside shutdown, an uncaught error still crashes the server as before.
- **Rationale:** Each guard sits at the narrowest boundary that owns the failure. The broken sink belongs to the logger that echoes into it. "Once we've decided to exit, nothing may skip the cleanup" belongs to the handler that decides. Arming process-wide handlers only after shutdown starts avoids hiding real bugs during normal operation, where a crash plus the boot resume sweep is the existing recovery. During shutdown the exit is already guaranteed and bounded by `awaitDaemons`, so swallowing costs nothing, while dying early leaks daemons.
- **Alternatives considered:** Moving the log line after teardown. That's insufficient: the EPIPE arrives on a later tick, so it still kills the process before the timers. A process-wide `uncaughtException` handler for the server's whole lifetime was rejected: it would turn every unexpected error into a silently half-broken server. Ignoring SIGPIPE-style errors only in the shutdown log call was rejected too: the crash also happens from ordinary log lines, before any signal. Detaching stdout entirely under a pipe was rejected because it breaks `| tee` logging users rely on.
- **Source:** autonomOS agent channel (TeamLead ↔ CodexGemini, 2026-09-30); isolated-instance repro and Codex A/B in the PR's Validation section.
