## ADR-141: One machine-wide slot for heavy local test runs; fleet-harness guards

- **Date:** 2026-10-01
- **Decided by:** Performance@autonomOS (agent); TeamLead@autonomOS approved the three guards after the 2026-10-01 overload.
- **Context:** Agents run tests on the same Mac as Terry's live fleet. On 2026-10-01 the load average hit 500-660 and his :3100 dashboard stopped responding. Contributors: a 50-agent statusline load rig, several isolated rigs with real agents, overlapping `node --test` runs, and the statusline/git spawn storm. #400 already queued pre-push gates behind a machine-wide lock, but a manual `make check` (or an `AUTONOMOS_INTEGRATION=1` run) and load rigs took no slot at all. Separately, four `tsx --test <file>` runs were found orphaned and hung for 5-6 days: ad-hoc runs had no test timeout, and when the agent's shell gave up, the node child kept running.
- **Decision:** (1) Every heavy local run takes the ONE machine-wide slot (`scripts/ci-gate-lock.sh`): `make check` routes itself through it (CI skips it), and a new `make load-test` does too. The lock is re-entrant per lock path (`AUTONOMOS_GATE_LOCK_HELD=<path>`), so the pre-push gate, which already holds it and runs `make check`, passes straight through. (2) `scripts/test-file.sh` is the ad-hoc runner: `--test-timeout` (5 min default) plus `--test-force-exit`, so a hung test fails AND the process exits even when a leaked handle would keep it alive (measured: the timeout alone left the process running), with git's location variables stripped. (3) Fleet harnesses use `__tests__/helpers/fleet-guard.ts`: `assertFleetSlot()` refuses a local run outside the slot, and `startLoadWatchdog()` aborts the run when the 1-minute load passes 2.5× cores. The statusline load test is the first user. Structural tests pin each piece (`make -n` routing, re-entrancy, refusal, watchdog, timeout + force-exit), each mutation-proven.
- **Rationale:** Queueing keeps throughput the same while removing overlap, which is what hurt the live server. Re-entrancy keyed to the lock path avoids the gate deadlocking on itself without letting an unrelated lock (e.g. the lock tests' own temp locks) pass through. Self-aborting harnesses bound the damage of a run that turns out heavier than expected; the abort names the reason.
- **Alternatives considered:** (a) Lock only in lefthook (status quo): misses manual and integration runs and rigs. (b) A global `--test-timeout` via NODE_OPTIONS: Node does not allow test flags there. (c) Kill orphaned test processes with a periodic sweep: treats the symptom and risks killing other agents' runs; timeout + force-exit makes a run end itself. (d) cgroup/nice limits: platform-specific and doesn't prevent overlap.
- **Source:** Performance@autonomOS CC session and TeamLead@autonomOS channel, 2026-10-01 (statusline load investigation, PR #481).
