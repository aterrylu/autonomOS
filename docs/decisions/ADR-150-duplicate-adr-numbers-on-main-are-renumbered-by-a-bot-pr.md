## ADR-150: Duplicate ADR numbers on main are renumbered by a bot PR

- **Date:** 2026-10-08
- **Decided by:** TeamLead@autonomOS (GO on the proposal, 2026-10-08); proposed and built by Decisions@autonomOS. It follows Terry's decision, the same day, to turn off the ruleset's up-to-date requirement.
- **Context:** ADR-114's duplicate-number check ran in PR CI, and it kept collisions off main only because main required branches to be up to date: CI always re-ran against the current main. On 2026-10-08 that requirement was turned off (ruleset 20360435, `strict_required_status_checks_policy: false`) to end update-branch loops. Now two PRs that each picked ADR-NNN can both pass CI and both merge. `make adr` reads open PRs, so this needs two allocations before either PR is pushed or a hand-picked number. It happened while writing this ADR: `make adr` offered 149, which another agent had announced but not yet pushed. On main, a duplicate turns every later PR's `check` red. It also failed the decisions-index workflow's Validate step, which then skipped the index regeneration. And at the time of writing nothing ran CI on main's own commits.
- **Decision:**
  1. The decisions-index job also runs on each push to main that touches `docs/decisions/ADR-*.md`. These runs only validate; the index stays hourly (ADR-147).
  2. On a duplicate NEW number, `scripts/decisions.ts fix-collisions` renumbers the file added LATER. "Later" is the position of its add-commit in main's history (`git rev-list --count`), never a timestamp, and a legacy entry always keeps its number. It reuses `renumber` (git mv + header, staged) and opens or updates ONE rolling PR, "docs(decisions): renumber colliding ADR", authored by aterrylu via RELEASE_PAT so nox approves it, with auto-merge on. The PR body names both merges and lists every `ADR-NNN` mention the later merge added outside `docs/decisions/`, for its owner to update. The bot never edits code. If main becomes valid some other way, the bot closes the open PR.
  3. Validation no longer stops the job. The index still regenerates on schedule, and a separate final step turns the run red.
  4. `check` names the commit that added each colliding file (outside shallow clones, where git would blame the one grafted commit for every file).
- **Rationale:** This keeps Terry's trade-off (no update-branch loops) while making the existing "later merger renumbers" rule mechanical. The fix lands through the normal gate, so the ruleset stays no-bypass. Renumbering by history order matches who actually merged later; commit dates reflect authoring or rebase time, not landing. Listing mentions instead of rewriting them keeps the bot out of code, where an `ADR-NNN` string may be quoted text, a test fixture, or a deliberate historical reference.
- **Alternatives considered:** Accept a red main and fix it by hand (every PR's CI blocks until someone notices, and the index stops updating). A GitHub merge queue (re-serializes merges, the cost Terry just removed). Reserve numbers in a shared file (a shared file every ADR PR edits, which is the hotspot ADR-114 removed). Have the bot also rewrite code mentions (it can't tell a reference from quoted text, and it would put production code in a bot PR). Rank files by commit date (squash commits carry authoring or rebase dates).
- **Supersedes:** nothing. It extends ADR-114 (the per-file layout and check) and keeps ADR-147 (hourly index).
- **Source:** autonomOS agent channel, 2026-10-08: ReleaseRollout's merge-rule announcement, then Decisions@ → TeamLead proposal and TeamLead's GO; the PR that added `fix-collisions`.
