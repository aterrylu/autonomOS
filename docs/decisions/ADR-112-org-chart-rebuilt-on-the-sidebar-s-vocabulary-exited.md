## ADR-112: Org chart rebuilt on the sidebar's vocabulary — exited-inclusive tree, tidy-tree layout, shared palette, shared agent menu

- **Date:** 2026-09-24 · **Decided by:** Terry (approved proposal v2: "fold the audit findings into the features"), designed + built by OrgChart@autonomOS, relayed via TeamLead. Context-menu reuse and drag conventions checked with Shortcuts@autonomOS.
- **Context:** A live audit of the Org Chart tab (isolated instance, 10 real Claude Code / Codex / Gemini agents) found nine problems, F1–F9: a needs-input card looked like an idle one; Daylight rendered dark tiles with invisible connectors (hardcoded `rgba(28,36,51)` cards, white 15% lines); a crashed manager scattered its team to the top level; clicking a card did nothing and hovering offered only a destructive trash overlay; Resume could never render; every root stacked in one tall column; status colors differed from the sidebar's (ADR-090); cards showed less than a sidebar row (no unread count, no recency).
- **Decision:**
  1. **Exited-inclusive tree, pruned in the client.** The chart reads a new `orgTreePoll` (`/api/agents/tree?includeExited=true`; the push bridge injects `buildAgentTreeNodes(agents, { includeExited: true })`, parity by construction). The core default stays exited-free, so the sidebar and MCP `get_org_chart` are unchanged. `pruneExited` draws an exited agent as a dashed **ghost** only when its subtree still holds a running agent; others hide behind a "Show N exited" toggle. Hiding only ever removes whole dead subtrees, so a running agent is never promoted to a root.
  2. **Tidy-tree layout** (`orgchart/layout.ts`, replaces `react-organizational-chart`): teams side by side, reportless roots on an "Unassigned" shelf, SVG elbow connectors (dashed on exited edges).
  3. **One palette.** `orgChartTokens(page)` derives every chart color from `THEMES[theme].page` plus `isLightBg`, and status colors are `statusLabelStyle`'s. Working = the sidebar's shimmer set; its card breathes a slate ring. Needs-input = the sidebar's amber (border + pulsing ring) plus a "N need you" strip. Reduced motion keeps the static ring. `UNREAD_COLOR` and `formatAge` moved to shared modules so the sidebar and the chart read one definition.
  4. **Click selects; opening is explicit** (Terry's pick at the live gate: navigating away on a single click was "unexpected and annoying"). A click SELECTS the card: the selected agent, its manager chain and its team stay lit and everything else dims, and a docked inspector opens beside the chart (status, recency, unread, runtime, permissions, preset, template, directory, clickable manager/reports, and Open terminal / Restart / Resume / ⋯). Double-click, Enter, or the inspector's Open terminal opens the agent (switchPane + focusTerminal + mark read). Arrow keys walk the chart (↑ manager, ↓ first report, ←/→ same-row neighbor). Esc clears the selection through the ADR-065 escape stack, and so does clicking empty canvas. Right-click / Shift+F10 opens `AgentContextMenu` unchanged (exited ghosts get Resume + Delete). The trash overlay and the card's inline kill/remove are deleted. A running card is a native `<button>` and an exited ghost a `<fieldset>`, so the ghost's inline Resume stays reachable to assistive tech. Focus and selection show as a themed outline, because the card's box-shadow is owned by its status animations. The inspector deliberately shows only data that exists today; analytics (time in state, tool and message counts, per-session usage) is a follow-up that needs server collection.
  5. **The menu is portaled to `<body>`.** Measured live: dockview wraps every pane in `.dv-render-overlay` with `transform` + `contain: layout paint`, which makes the pane the containing block for `position: fixed`, so an in-pane menu opened offset by exactly the sidebar width and header height (+256, +81). Any fixed overlay rendered inside a dockview pane needs a portal.
- **Rationale:** each finding closes as a side effect of how the chart is now built, not via a separate fix list, so the problems can't come back piecemeal. Each fix is pinned by a mutation-verified test (11 mutations, all red).
- **Alternatives considered:** **Flip the core `includeExited` default** — rejected: it would change MCP `get_org_chart` and the sidebar. **Draw every exited agent** — rejected: managers that reap short-lived workers would bury the chart. **Keep `react-organizational-chart` and restyle it** — rejected: its flex layout can't place teams side by side with a shelf, and its CSS connectors can't dash per edge. **A chart-only context menu** — rejected: two menus for one agent would drift.
- **Follow-ups (approved sequence):** PR 2 team rollups + collapse; PR 3 message flow with a text preview (a new `message.routed` event, server-capped preview, text-only render); PR 4 drag to reassign (always confirm; the chart becomes a second re-parent surface next to the Set-manager submenu; pointer events, never `draggable`/`DRAG_TYPE`) plus "+ Helper"; PR 5 pan/zoom/minimap/lenses. The #383 passive-label recency fade (`recencyLabelOpacity`) is wired into the card, so an idle card's label fades exactly like its sidebar row.
