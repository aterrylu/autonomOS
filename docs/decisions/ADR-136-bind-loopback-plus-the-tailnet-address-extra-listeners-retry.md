## ADR-136: Bind loopback plus the tailnet address; extra listeners retry until their address is up

- **Date:** 2026-10-01
- **Decided by:** Terry (human) for the goals: "most people install it on a remote server, so they must make sure it's safe; recommend Tailscale; restarts must keep working", and keep the all-interfaces default. TeamLead@autonomOS proposed the canonical ranking and approved the host-list design. SecurityFix-Auth@autonomOS found that a tailnet-only bind breaks the CLI, then designed and implemented this.
- **Supersedes:** ADR-054 (part: its rejection of tailnet-IP binds because "the bind fails with EADDRNOTAVAIL if tailscaled isn't up yet")
- **Context:** autonomOS is usually reached on a remote server over Tailscale. Its default bind is all interfaces (ADR-054), which also exposes it on the LAN and, on a server with a public address, the internet. Two ways to narrow it didn't work:
  - **Binding only the tailnet IP.** ADR-054 rejected it because the bind fails at boot when Tailscale isn't up yet. Worse, autonomOS assumes it answers on localhost: `autonomos status`, `autonomos auth unlock`, the post-install health check, and the pid file's "is the old server alive?" probe all talk to `localhost`. A tailnet-only bind breaks every one of them (`cli-args.ts` already warned "use a loopback address, not another specific IP").
  - **`tailscale serve`**, the canonical Tailscale way. It proxies every visitor through this machine, so they all arrive from loopback, and the per-device protections (ADR-124 throttle, ADR-135 new-device lock) treat all of them as this machine. Until a trusted-proxy mode reads Tailscale's identity headers (a separate, scoped piece of work), serve is not recommended.
- **Decision:**
  1. **`--host` / `AUTONOMOS_HOST` takes a comma-separated list**, e.g. `127.0.0.1,100.x.y.z` or `127.0.0.1,<magicdns-name>`. The FIRST address binds exactly as a single `--host` always has, so loopback keeps the CLI, health check and pid-file probe working. A boot warning appears if the first entry isn't loopback.
  2. **Every further address gets its own listener on the same port, serving the same app**: the same routes, CSRF guard, auth, throttle, new-device lock and WebSocket injection, proven by a real-server test on the second listener.
  3. **An extra address that isn't available yet is retried in the background** every 5s (EADDRNOTAVAIL, ENOTFOUND/EAI_AGAIN for a name that doesn't resolve yet, EADDRINUSE). Node re-resolves a name on each attempt. The log is bounded: one line when it starts waiting, one when it binds. Errors that waiting can't fix are logged once and not retried. **An address another process is already SERVING (EADDRINUSE) is not "not up yet"**: a device opening it reaches that process, possibly a fake sign-in page collecting the token (SecurityAudit, #480). It gets a distinct `⚠ SECURITY` warning naming host:port and, where `lsof` can tell, the owner's pid, repeated at most once a minute while it lasts, plus a line when autonomOS takes the address back. It is still retried. The dashboard has no server-wide notification channel yet (SystemWarning is per agent), so surfacing it there is a follow-up. Loopback is served at once, so **a restart never fails on it**. The listeners close on shutdown.
  4. **"Network bind"** (which drives the weak-token rules and the perf-mode loopback gate) now means any non-loopback entry, or no host at all.
  5. **The recommended remote setup**, as documented in the README, guide and install output:
     - **(a) Recommended:** Tailscale with `--host=127.0.0.1,<tailnet-ip-or-name>`, opened at `http://<magicdns-name>:<port>`. It isn't exposed on LAN or public interfaces, the traffic is WireGuard-encrypted, the per-device protections see real tailnet addresses, and restarts are safe.
     - **(b) The default all-interfaces bind** is presented as it is, with the honest note that it exposes every network the machine is on, and to use it only behind a host firewall limited to the Tailscale interface (a ufw recipe is given).
     - **(c) `tailscale serve`:** "not yet", with the reason.
     - **(d) Google Cloud IAP:** keep a bind on the VM's internal interface, because IAP doesn't reach loopback, and limit the firewall to `35.235.240.0/20`.
     - **(e) SSH tunnel:** works with a loopback bind.
  6. **Service installs and updates preserve a list.** `install-service --host=` bakes it verbatim, `install.sh` keeps it when re-rendering (a test reads its grep pattern from the script), a source install's `.env` migration carries it, and upgrades don't touch the service file.
- **Rationale:**
  - **A list keeps one code path and one meaning for `--host`.** Loopback-first preserves every localhost assumption without touching the CLI, the pid file or health checks.
  - **Background retry, rather than blocking boot on the address,** makes restarts reliable in both directions. Loopback (and the operator's local tools) is never held hostage by Tailscale's start order, and the tailnet listener appears as soon as it can.
  - **Same app object, so the guards can't drift.** Serving the second listener from the same Hono app is what guarantees the CSRF guard and the lock apply there, rather than a second configuration that could diverge.
- **Alternatives considered:**
  - **Wait for the address before listening at all.** Rejected: the CLI and health check would see nothing until Tailscale is up, or would never see the server if it isn't.
  - **Teach the CLI and pid file to use the bound host.** Rejected: the localhost assumption lives in four places across the CLI and server, and the pid-file liveness probe affects mutual exclusion (ADR-029). Keeping loopback first changes none of them.
  - **Recommend a host firewall only.** Kept as the restriction for the all-interfaces default. Not the primary recommendation, because pf on macOS is fiddly and a firewall is easy to forget on a new machine.
  - **Recommend `tailscale serve` now.** Rejected until trusted-proxy support exists, because of the loopback blind spot above.
- **Source:** TeamLead@autonomOS channel, 2026-10-01 (Terry's goals and TeamLead's canonical ranking). PR `terry/docs-tailnet-iap`.
