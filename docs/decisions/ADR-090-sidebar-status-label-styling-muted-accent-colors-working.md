## ADR-090: Sidebar status-label styling — muted-accent colors + working shimmer

- **Date:** 2026-08-26 — **Decided by:** Terry, via TeamLead, after a multi-round mockup iteration (like recency/ADR-088). Built as a fast-follow after v0.6.0.
- **Context.** The sidebar's bottom-line status label (`agentStatusLabel`: Working / Ready / Idle / Needs input / …) rendered as a flat `statusFg` at 75% opacity — no color, and an actively-*working* agent looked identical to an idle one. Terry wanted (1) "working" to read as BUSY at a glance, and (2) "Needs input" to pop in amber.
- **Decision.** Color the status **label text** by status (labels only — the status **dots** keep their existing bright colors, deliberately, to avoid a wider status-icon-system change). Active-work statuses (`working` / `tool_running` / `compacting` / `orchestrating`) animate a **seamless slate-blue shimmer** (a symmetric gradient clipped to the text, translated one full period so the loop doesn't snap; all active rows share the one animation, so they sweep **in sync**). Static statuses: ready/idle → muted sage, needs_input → amber, error → muted red, stopped/unknown → gray. The mapping lives in a pure, tested `statusLabelStyle.ts` (sibling of `recency.ts`).
- **Theme-aware (mandatory, learned from ADR-088).** The palette is chosen by `isLightBg(page.bg)` (reused from recency). The dark palette is Terry's approved set (`#7e97b3 / #7d9a80 / #eab308 / #d98a6a / #a3a3a3`); on the light theme those mid-tones collapse to ~2:1 contrast on near-white (amber `needs_input` measured 1.84:1, the shimmer highlight 1.29:1 — invisible), so light themes use darkened variants of the same hues (`#3f5f85 / #46714f / #8a6900 / #b0503a / #6b7178`), each ≥4.5:1 on `#fafaf8`. Shimmer is two theme classes (`.status-shimmer` / `.status-shimmer-light`).
- **Robustness.** The shimmer uses `color: transparent` + `background-clip: text`; BOTH `prefers-reduced-motion` AND an `@supports not (background-clip: text)` block fall back to the visible base color, so a busy label can never render as invisible transparent text. Animation runs only on active-work rows (a few at a time) — cheap regardless of fleet size. Coexists with the recency fade (ADR-088): recency fades the timestamp, this colors the label — orthogonal; the label stays full-strength on a faded-timestamp row. `statusLabelStyle`'s switch is `never`-exhaustiveness-guarded so a future status can't silently fall through to gray.
- **Alternatives considered and rejected (Terry's mockup journey):** *bright dot-matched label colors* — "too bright"; *pure monochrome* — considered, then → *muted accents* (his pick, "keep color but calm it way down"). Working animation: *rainbow sweep* (his literal first idea — rejected: clashes with the palette, weakest colorblind coherence), *opacity pulse*, *animated ellipsis* — all rejected for the shimmer. Shimmer sync: *staggered* and *drift* (varied per-row phase/speed) — "too chaotic" → **synced**. Muting the dots too — deferred (wider status-icon-system change).
- **Test evidence.** `statusLabelStyle.test.ts` pins both palettes' exact hexes, the active-work-only shimmer rule, the no-gold invariant, and (via `never`) exhaustiveness; `Sidebar.statusLabel.dom.test.tsx` drives a real SessionRow on both themes — dark → `.status-shimmer` + dark colors, light → `.status-shimmer-light` + darkened colors — and pins coexistence with the recency fade. Mapping mutation-verified RED. CSS shimmer/@supports/reduced-motion are not jsdom-testable (keyframes/queries don't apply) — verified visually across void/midnight/daylight.
