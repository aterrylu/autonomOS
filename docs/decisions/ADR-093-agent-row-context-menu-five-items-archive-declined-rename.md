## ADR-093: Agent-row context menu — five items, archive declined, rename deferred

- **Date:** 2026-08-28
- **Who:** Terry (design locked over three mockup rounds; picks relayed via TeamLead), implementation by the Shortcuts agent
- **Context:** There was no in-UI way to act on an agent beyond click-to-focus and pin. Killing/resuming/reassigning/deleting an agent, or dismissing an exited-record from the Projects panel (the "exited gemini-test clutter" incident), had no discoverable affordance — the org chart directs users to the MCP `set_manager()` tool, and there was no `onContextMenu` anywhere in the dashboard. Terry asked for a right-click menu ("archive/kill, restart, and so on"). Designed as a proposal + mockup first (artifact accf2bfd), iterated to a locked spec.
- **Decision:**
  1. **Five items**, running context: **Open · Kill · Restart · Set manager ▸ · Delete…**, grouped by separators into **process ops** (Open/Restart/Kill) / **record op** (Set manager) / **danger** (Delete), with the danger group in a subtle red-tinted block. **Exited context** (Projects panel): Kill/Restart collapse to **Resume** (bold primary); Open is omitted (no live pane); Set manager + Delete apply only when the exited row resolves to an autonomOS agent record.
  2. **Archive DECLINED.** An `archived` "hide-but-keep" flag was designed (the clutter fix) but Terry chose Delete alone — accepting it is irreversible — over a new record-state. Recorded here as considered-and-declined; the `AgentStatus` comment already anticipates `archived` as a strictly-additive state, so it can return cleanly if delete-regret shows up.
  3. **Rename DEFERRED** (net-new mutation, out of this PR). Claude Code owns session names via the JSONL `customTitle` (titleCache reads it, trusted over the SDK), so a dashboard rename must either push `/rename` into a live CC session (CC stays owner; live-CC-only) or make the record name authoritative (any provider, but diverges from the TUI title). That decision, plus the PTY-injection concern, is deferred to be revisited alongside the Hand-Off Queue's injection machinery. **Future rename design (Terry, 2026-08-29 — recorded, NOT built): rename = restart the session under the new name** — kill → respawn-with-resume using the `--name` spawn flag — behind an explicit pre-action warning ("Renaming will restart this session; the conversation resumes. Continue?"). This dissolves the ownership wrinkle above: no PTY injection into a live TUI and no record-vs-CC-title divergence, because the new name is simply the resumed session's spawn-time name. **Build-time caveat to verify:** a session that ever ran `/rename` carries a `customTitle` in its JSONL, and titleCache may override the spawn name on resume — check that interaction before trusting the approach universally (may need to clear/ignore a stale `customTitle`, or document that `/rename`-ed sessions keep their in-session title).
  4. **Interaction invariants:** the contextmenu trigger is scoped to the ROW element (`preventDefault` there) — NEVER a document-level handler, because xterm owns right-click inside terminal panes (ADR-072). Dismissal rides the ADR-065 escape stack (`pushEscapeCloser` on open); click-away is a menu-scoped capture-phase `pointerdown` listener; the menu is keyboard-navigable (`role=menu`/`menuitem`, ↑/↓, Enter, Esc). Delete is guarded by an **in-place inline confirm** ("Delete…" → "Delete permanently? · Cancel / Delete") — no modal, no undo-toast — so the permanence warning lands at decision time and a stray click can't destroy a record. Menu items **never wrap** (`white-space: nowrap` + a menu `min-width`), pinned by a test against the longest label. **Set manager opens a nested flyout submenu** (revised at Terry's visual gate — see below): hover-intent (open ~180ms / close ~260ms grace so diagonal travel doesn't flicker it) plus click / ArrowRight / Enter; it nests its OWN escape-stack closer so Escape peels the submenu before the menu (LIFO), ArrowLeft returns, and it flips to the left edge near the right side, caps height + scrolls for long fleets, and truncates long candidate names with an ellipsis + title tooltip.
  5. **Implementation:** one `AgentContextMenu` component serves both surfaces via a normalized `AgentMenuTarget` (the Projects exited row carries no agent id — the caller resolves it from `sessions`/`exitedSessions` by matching either id space). Restart is composed from the two existing endpoints (kill → attach; there is no per-agent restart route). `setManager`/`restartSession` store actions and an `agentsApi.manager` client method are added (the server `POST /:id/manager` route already existed, previously reachable only via MCP).
- **Rationale:** Design-first (mockup rounds) kept the scope debate cheap — archive and rename were both cut *before* code, and folding the archive/rename choice into the item-set variants let one pick answer several open questions. The normalized-target shape avoids duplicating the menu for the two session data models. Inline-confirm over undo-toast because a hard delete `unlink`s the record file — an honest undo would require deferring the delete; the inline confirm needs no such plumbing and can't misfire.
- **Alternatives considered:** archive flag (declined, above); rename now (deferred, above); an undo-toast for delete (rejected — no deferred-delete plumbing, and a delete is irreversible); an in-place drill-in for Set manager (shipped first, then **replaced by a nested flyout submenu at Terry's visual gate** — "I want it to open another menu to show the list of managers, I like that better"); wiring only running rows (rejected — the clutter-delete lives on the exited Projects surface, the feature's headline value).
