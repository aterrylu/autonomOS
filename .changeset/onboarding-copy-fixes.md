fix(dashboard): first-run copy — drop internal tool names and stale claims from user-facing text

Findings F5 from the onboarding audit (a non-technical newcomer's first ten minutes, walked on an isolated instance). Every change is copy; no behaviour changes.

- **Login screen** now says how to get the token back: "Find your token in the install output, or run `cat ~/.autonomos/token` on the machine running autonomOS" (was "…or in `~/.autonomos/token`", a dotfile path a non-developer can't open). The path is the default install's; a non-default `AUTONOMOS_CONFIG_DIR` keeps its token under that dir, and a pinned `AUTONOMOS_TOKEN` ignores the file (both documented in `.env.example`).
- **Empty states speak to the person, not the MCP surface.** Org chart: "Create an agent, then ask it to spawn helpers — managers and their reports appear here" (was "use `set_manager()`"). Presets: plain-language explanation that names the real `+ New` button (was "New preset", a button that doesn't exist, plus `create_env_preset`). Schedules: "created by agents, not by hand" (drops the `create_schedule` name; keeps the ask-an-agent examples). Notifications: "When an agent sends you a message, it appears here" (was "via `--brief`").
- **Runtime cards**: the not-installed card says "After installing, reopen this panel (or reload the page)" (was "Restart server after installing"; binary detection re-runs on every panel open, and a daemon restart neither re-reads PATH nor exists on every install path). The hooks badge reads "Live status needs a one-time setup for this runtime" — currently unreachable, every provider declares `hooks.requiresSetup: false`, so this is future-proofing, not a visible change.
- **`.env.example`** no longer claims auth can be disabled ("Leave unset or empty to disable auth (open access)"); auth has been always-on since the token work, as the README already says. Names the real token location: `$AUTONOMOS_CONFIG_DIR/token`, default `~/.autonomos/token`, `.autonomos-dev/token` under `make dev`.
- **`AGENTS.md`** synced with `CLAUDE.md` on four stale facts a newcomer's AI assistant would read: the layout engine (dockview, not a binary tree), the spawn flags (permission modes per ADR-045/061, not a lone `--dangerously-skip-permissions`), where the HTTP MCP server lives (internal control socket, ADR-055, not "Claude Desktop, CI"), and the shared tool list — which in **both** files was missing the four env-preset tools (`list_env_presets`, `create_env_preset`, `update_env_preset`, `delete_env_preset`) that `mcp/tools.ts` defines and both servers register.
